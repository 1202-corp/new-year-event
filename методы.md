При смене окраски шара от проекционных лучей цветовая сегментация перестаёт работать. Поэтому фокус смещается на форму и движение объекта. Надёжные методы включают детекцию кругов и контуров шарообразных объектов, отслеживание по оптическому потоку и фильтрацию движения. Ниже рассмотрены основные подходы, их плюсы и минусы, а также примеры кода на Python/OpenCV.

Детекция по форме (контуры и преобразование Хафа)
-------------------------------------------------

*   **Преобразование Хафа для кругов:** работает на градациях серого. Сначала размываем (например, `GaussianBlur`) для удаления шума, затем вызываем `cv2.HoughCircles`. Код может выглядеть так:
    ```python
    gray = cv2.cvtColor(frame, cv2.COLOR_BGR2GRAY)
    gray = cv2.medianBlur(gray, 5)
    circles = cv2.HoughCircles(gray, cv2.HOUGH_GRADIENT, dp=1.2, minDist=50,
                               param1=50, param2=30, minRadius=10, maxRadius=100)
    if circles is not None:
        circles = np.uint16(np.around(circles))
        for (x, y, r) in circles[0, :]:
            cv2.circle(frame, (x, y), r, (0, 255, 0), 2)
    ```
    Этот метод сразу находит центры и радиусы всех круглых объектов в заданном диапазоне. **Плюсы:** нечувствителен к цвету, даёт готовую позицию и размер. **Минусы:** сильно зависит от параметров (`param1`, `param2`, порогов Canny внутри), может промахнуться, если границы круга неявные или шумные. Кроме того, `HoughCircles` достаточно тяжёл для высоких разрешений, поэтому на практике часто обрезают кадр до области интереса (ROI) вокруг предполагаемого положения шара.
*   **Поиск контуров на бинаризованном изображении:** переводим кадр в серый, размываем, затем находим границы через Canny или пороговую фильтрацию. После этого `cv2.findContours` извлекает контуры. Например:
    ```python
    gray = cv2.cvtColor(frame, cv2.COLOR_BGR2GRAY)
    blurred = cv2.GaussianBlur(gray, (7,7), 0)
    edges = cv2.Canny(blurred, 50, 150)  # или использовать cv2.threshold
    contours, _ = cv2.findContours(edges, cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_SIMPLE)
    for cnt in contours:
        area = cv2.contourArea(cnt)
        if area > 500:  # фильтрация по минимальной площади
            (x, y), radius = cv2.minEnclosingCircle(cnt)
            perimeter = cv2.arcLength(cnt, True)
            circularity = 4*np.pi*area/(perimeter*perimeter)
            if radius > 10 and circularity > 0.7:
                cv2.circle(frame, (int(x), int(y)), int(radius), (0,0,255), 2)
    ```
    Здесь мы фильтруем найденные контуры по площади, радиусу и форме (круглости). **Плюсы:** гибкость и скорость — можно детектировать объекты практически любой формы и фильтровать лишнее. Контуры выделяются независимо от цвета (работая с градиентом яркости). **Минусы:** требуется подобрать пороги Canny или бинаризации, размывать кадр и убирать шум, иначе контур шара может быть разрывным. Иногда шар может быть разделён на несколько контуров (например, из-за неровностей освещения), поэтому может потребоваться морфологическое замыкание. Тем не менее, комбинация `blur + Canny + findContours` — проверенный подход.

Предобработка и фильтрация
--------------------------

*   **Сглаживание (размытие):** перед детекцией полезно применять `cv2.GaussianBlur` или `medianBlur` для подавления случайного шума в кадре. Это упрощает выделение контура или градиента шарика.
*   **Морфологические операции:** после пороговой фильтрации или получения маски полезно применить **эрозию** и **расширение** (`cv2.erode`, `cv2.dilate` или `cv2.morphologyEx` с `MORPH_OPEN/MORPH_CLOSE`) для удаления мелких артефактов. Например, при использовании маски (`cv2.inRange` или результат Canny) серию эрозии/дилатации можно использовать для «очистки» маленьких пятен. Это улучшает стабильность последующего поиска контуров.
*   **Бинаризация по яркости:** если известно, что шар в среднем светлый, можно использовать пороговую фильтрацию по значениям яркости (например, адаптивный порог или Otsu). Но из-за проекции цвета яркость шара тоже меняется, поэтому фиксированный порог может не подойти. В таких случаях лучше применять Canny (он реагирует на градиенты, а не абсолютное значение).
*   **Фильтрация по размеру и форме:** поскольку шар имеет заданный размер, можно игнорировать контуры, чьи размеры вне диапазона (смотреть на `cv2.contourArea` или радиус `minEnclosingCircle`). Также можно вычислять _круглость_: отношение площади контура к площади его описанного круга или формулу `4π·Area/(Perim²)`. Для шара это значение близко к 1, что и используется для отбраковки «нерыдных» объектов.

Отслеживание и оптический поток
-------------------------------

*   **Оптический поток Лукаса–Канаде:** позволяет отслеживать отдельные точки между кадрами. Классический алгоритм: находим хорошие угловые точки (Shi–Tomasi) на шаре и передаём в `cv2.calcOpticalFlowPyrLK`, чтобы они сместились в новом кадре. Так можно оценить движение шарика. Однако у белого шарика мало текстуры, так что надёжность низка. В любом случае этот метод полезен для сглаживания позиции между полными детекциями или при кратковременной потере сигнала. Как описано в документации, Lucas–Kanade работает для разреженного набора точек, а Farneback — для плотного потока.
*   **Плотный оптический поток (Farneback):** оценивает движение для всех пикселей с помощью `cv2.calcOpticalFlowFarneback`. Может показать глобальное смещение всего кадра (полезно, если шар — единственный движущийся объект), но он же вычислительно дорогой и может путаться, если фон динамичен.
*   **Калманов фильтр:** часто используется для сглаживания трекинга. На вход Калману подаём обнаруженную позицию шара, а фильтр предсказывает его новое положение по прошлой скорости. Это помогает при кратковременных помехах или пропусках детекции.
*   **Трекеры OpenCV:** есть готовые алгоритмы (KCF, CSRT, MOSSE и др.), которые при инициализации рамкой объекта (bounding box) продолжают его отслеживать каждый кадр. Например, `cv2.TrackerMOSSE_create()` очень быстрый, а `cv2.TrackerKCF_create()` или CSRT — более устойчивые к деформации и смене масштаба. Однако они ориентируются на все характеристики объекта (цвет, текстуру). В условиях меняющегося окраса шарика трекер может «сбиться», поэтому обычно его перезапускают после каждой успешной детекции формы. Тем не менее, комбинирование детектора (контуры/Хафа) с трекером позволяет снизить вычисления: не искать шар каждый кадр, а довериться трекеру, если он ещё «держит цель».

Вычитание фона и детекция движения
----------------------------------

*   **Background Subtraction (вычитание фона):** классический приём — выделять движущиеся объекты на статическом фоне. Алгоритмы MOG2, GMG в OpenCV строят модель фона и вычитают её из текущего кадра. Но они предполагают **статичный фон**[docs.opencv.org](https://docs.opencv.org/4.x/d8/d38/tutorial_bgsegm_bg_subtraction.html#:~:text=If%20you%20have%20an%20image,It%20complicates%20things). Из-за проекционного освещения фон фактически «меняется» (цветной фон постоянно меняется), поэтому фонообразующие методы будут считать искажения фона движением, получая много ложных пятен. Если же фон действительно неизменен (а проекция влияет только на шар), такой метод может сработать. В общем же случае вычитание фона для проектора менее надёжно[docs.opencv.org](https://docs.opencv.org/4.x/d8/d38/tutorial_bgsegm_bg_subtraction.html#:~:text=If%20you%20have%20an%20image,It%20complicates%20things).
*   **Детектирование движения:** простой способ — сравнивать кадры (или кадр с фоновым усреднением) и искать большие изменившиеся области. Это грубый метод, но если шар — единственный движущийся объект, его область появится на разности кадров. Стоит учитывать, что резкая смена проекции может «притвориться» движением фона.

Практические рекомендации и производительность
----------------------------------------------

*   **Оптимизация разрешения и ROI:** для реального времени обычно не используют высокое разрешение. Часто уменьшают кадр (например, до 640×480 или ROI вокруг предыдущей позиции) перед детекцией. Это ускоряет `HoughCircles` и `findContours` пропорционально.
*   **Частичный детект и трекинг:** можно выполнять полную детекцию (Хафа/контуры) не каждый кадр, а реже (скажем, каждые 5–10 кадров). Между ними доверяться быстрым методам (оптический поток или трекеру).
*   **Использование морфологии:** показано, что комбинация эрозии и дилатации улучшает чистоту масок, что ускоряет поиск контура и снижает ложные срабатывания.
*   **Аппаратные ускорения:** OpenCV поддерживает GPU-модули (`cv2.cuda`) и оптимизации SSE/AVX. В Python также можно использовать `cv2.UMat` или Numba для ускорения критичных частей.
*   **Гистограмма градиентов или другие дескрипторы:** при необходимости дополнительной устойчивости можно вычислять HOG или Hu-моменты контура, чтобы отличать гладкий шар от, скажем, резкой проекционной границы. Но это усложняет систему.

Итого, надёжное отслеживание в описанных условиях достигается сочетанием **гибкой детекции по форме** и **движению**. Контурный метод с фильтрацией по размеру и форм-фактору (цифр-овал), а также `HoughCircles`, дают прямое положение шара без учёта его цвета. Оптический поток и трекеры обеспечивают непрерывность между кадрами. Предварительная обработка (размытие, морфология) и фильтрация улучшают качество. В итоге получается система, устойчивая к смене цвета от проектора и способная работать в реальном времени на обычной веб-камере.

**Пример кода (упрощённый)** для сравнения методов:

```python
import cv2, numpy as np

cap = cv2.VideoCapture(0)
while True:
    ret, frame = cap.read()
    if not ret: break
    gray = cv2.cvtColor(frame, cv2.COLOR_BGR2GRAY)
    blurred = cv2.GaussianBlur(gray, (7,7), 0)

    # HoughCircles
    circles = cv2.HoughCircles(blurred, cv2.HOUGH_GRADIENT, 1.2, 50,
                               param1=50, param2=30, minRadius=10, maxRadius=100)
    if circles is not None:
        circles = np.uint16(np.around(circles))
        for (x, y, r) in circles[0, :]:
            cv2.circle(frame, (x, y), r, (0,255,0), 2)

    # Контуры по Canny
    edges = cv2.Canny(blurred, 50, 150)
    contours, _ = cv2.findContours(edges, cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_SIMPLE)
    for cnt in contours:
        area = cv2.contourArea(cnt)
        if area > 300:
            (x,y), r = cv2.minEnclosingCircle(cnt)
            if r > 10:
                cv2.circle(frame, (int(x), int(y)), int(r), (255,0,0), 2)

    cv2.imshow("Frame", frame)
    if cv2.waitKey(1) == 27:
        break
cap.release()
cv2.destroyAllWindows()
```

В этом фрагменте сначала выделяются круги через Хафа, затем — контуры. Константы (`param1`, `param2`, пороги Canny, `minRadius`) подбираются эмпирически. По необходимости можно добавить морфологию после Canny или Threshold, а также комбинировать с оптическим потоком. Главное — использовать геометрические признаки (окружность, площадь, контур) и не полагаться на стабильность цвета шара.

**Источники:** стандартные руководства OpenCV по HoughCircles и findContours, а также практические примеры детекции шарика из открытых источников[docs.opencv.org](https://docs.opencv.org/4.x/d8/d38/tutorial_bgsegm_bg_subtraction.html#:~:text=If%20you%20have%20an%20image,It%20complicates%20things).
